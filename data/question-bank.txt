@theory-with-examples 2 4
Q Why do we drop constants and lower-order terms in Big-O, and what does O(n log n) mean in practice?
A Big-O describes growth rate for large n; constants/lower terms don't change growth class; n log n ≈ sorting cost, e.g. 1e5 → ~1.7e6 ops.
Q In `for i in 1..n: for (j = i; j <= n; j *= 2)`, why does the inner loop run only a logarithmic number of times?
A j doubles every iteration instead of increasing by 1; it passes n after about log2(n/i) steps; so the total work is a sum of logarithms, at most n log n
Q Difference between best, average and worst case — give an example algorithm where they differ.
A e.g. quicksort O(n log n) avg vs O(n^2) worst; linear search O(1) best vs O(n) worst; interviews usually quote worst case.

A An ordered map is a balanced BST with O(log n) operations; it keeps keys sorted, so it supports in-order iteration and floor/ceil/range queries; a hash map gives O(1) average (O(n) worst case) with no order; use the ordered map only when order or range queries are needed

A C++ priority_queue (max by default, greater<> for min), Java PriorityQueue (min by default), Python heapq (min); push/pop O(log n), top O(1).

A Every existing element must shift one position to the right; the cost grows with the number of elements (O(n) per insert); a deque (or linked list) inserts at the front in O(1)

# ===================== STEP 2: Sorting =====================
@selection-sort 2 3
Q Walk through the first pass of selection sort on [64, 25, 12, 22], and explain why selection sort is not stable.
A Find the minimum 12 and swap it with the first element, giving [12, 25, 64, 22]; the next pass places 22 at index 1; it is not stable because a long-distance swap can jump an element over an equal one and change their relative order
Q How many swaps does selection sort make, and when is that useful?
A Selection sort does at most n - 1 swaps, one per pass; that is useful when writing to memory is much more expensive than comparing

@bubble-sort recursive-bubble-sort 2 3
Q Explain bubble sort and the optimisation that makes its best case O(n).
A Adjacent swaps push the largest to the end each pass; if a pass makes no swaps the array is sorted → stop early; best O(n), worst/avg O(n^2); stable.
Q How do you write bubble sort recursively?
A One pass bubbles max to index n-1, then recurse on n-1; base case n==1.

@insertion-sorting recursive-insertion-sort 2 3
Q Explain insertion sort and when it beats O(n log n) sorts.
A Insert each element into the sorted prefix by shifting larger elements right; O(n^2) worst, O(n) on nearly sorted data; stable, in-place; good for small or nearly sorted arrays.

@merge-sorting 3 5
Q What is the key idea of merge sort's merge step, and why is merging two sorted halves easy?
A Keep a pointer at the front of each sorted half; repeatedly take the smaller front element; when one half runs out, copy the rest of the other; it works because the smallest remaining element is always at one of the two fronts
Q Why is merge sort preferred for linked lists and external sorting?
A Merge needs only sequential access, no random access; linked-list merge needs no extra array; works on chunks that don't fit in memory.

@quick-sorting 3 5
Q What does the partition step guarantee about the pivot, and why does that make the recursion work?
A After partitioning, the pivot is at its final sorted position; everything on its left is ≤ pivot and everything on its right is ≥ pivot; so the two sides can be sorted independently and never need to be merged
Q How do you avoid the O(n^2) worst case?
A Random pivot or median-of-three; three-way partition for many duplicates.

@introduction- 1 3
Q Define full, complete, perfect and balanced binary trees.
A Full: every node 0 or 2 children; complete: all levels full except last, filled left to right; perfect: all internal nodes have 2 children and leaves at the same level; balanced: height O(log n) (|h(left) - h(right)| ≤ 1).
Q Why does a balanced binary tree with n nodes have a height of about log2(n)?
A Each level can hold twice as many nodes as the level above; a tree of height h holds up to 2^(h+1) - 1 nodes; so with full levels, n nodes need a height of about log2(n); a skewed tree can instead have height n - 1

Q How do you do postorder iteratively?

A Hash = sum of c * base^k mod p; slide by removing the outgoing char's contribution and adding the new one in O(1); compare hashes and verify on match (collisions); O(n+m) average; double hashing reduces collisions.

@z-function 4 3
Q What does the Z-array store and how is it used for pattern search?
A z[i] = length of the longest substring starting at i that matches a prefix; build for pattern + '$' + text; matches where z[i] == |pattern|; O(n) using the [l, r] window.

@kmp-algorithm-or-lps-array 4 4
Q What is the LPS array and how does KMP use it?
A lps[i] = length of the longest proper prefix that is also a suffix of pat[0..i]; on mismatch jump j = lps[j-1] instead of restarting; O(n+m).

@shortest-palindrome 5 2
Q How does LPS/KMP give the shortest palindrome by adding characters in front?
A Compute LPS of s + '#' + reverse(s); the last value is the longest palindromic prefix length L; prepend reverse(s[L..]).

@longest-happy-prefix 4 2
Q What is the answer in terms of the LPS array?
A The LPS value at the last index is the length of the longest proper prefix that is also a suffix; the answer is s[0 .. lps[n-1]); if that value is 0 the answer is an empty string

@prime-factorisation-of-a-number 2 3
Q How do you factorise one number, and many numbers efficiently?
A Trial division up to √n dividing out each factor, leftover > 1 is prime: O(√n); for many queries precompute the smallest prime factor (SPF) sieve and divide repeatedly: O(log n) per query.

@count-primes-in-range-l-to-r 3 3
Q How do you answer many range-prime-count queries?
A Sieve up to max R, build prefix counts of primes; answer = prefix[R] - prefix[L-1]; O(N log log N + Q). Segmented sieve for large ranges.
